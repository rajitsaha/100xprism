## How it works

100xPrism ships 68 modules — markdown files with YAML frontmatter in `modules/`. Your AI
tool reads them and follows them: running commands, enforcing thresholds, looping until
checks pass. Adapters render each module into each tool's native format:

| Tool | Scope | What arrives |
|:--|:--|:--|
| **Claude Code** | global, `~/.claude/skills/` | Must-have skills + `100x-resolver` + a `/100x <workflow>` route |
| **Cursor** | per project, `.cursor/rules/` | Must-have `.mdc` rules + resolver; catalog in `.cursor/100xprism-catalog/` |
| **Codex** | per project | Compact `AGENTS.md`, must-have skills in `.agents/skills/`, catalog in `.agents/100xprism-catalog/` |
| **Pi** | per project or Pi package | Must-have `.pi/skills/` + resolver; extensions ship disabled |
| **Hermes/OpenClaw** | global, `~/.hermes/skills/100xprism/` | Skills with descriptions shortened to fit Hermes's ~57-character index |

Modules not installed as skills stay in a catalog on disk and are loaded on demand — see
[Context modes](#context-modes). Windsurf, Copilot, Gemini and Antigravity were supported
through v2.x and removed in v3.0.0.

## Installation

### Step 1 — Global setup (once per machine)

```bash
# npm — macOS, Linux, Windows (Node.js 18+)
npm install -g 100xprism && 100xprism install

# curl — macOS / Linux
curl -fsSL https://raw.githubusercontent.com/rajitsaha/100xprism/main/get.sh | bash
```

Both clone the toolkit to `~/100xprism`. The installer first removes legacy startup
hooks, stale command links and any old 100xPrism dashboard process, asks to confirm the
Claude Code install, then lets you toggle components:

| Component | Default | What it does |
|:--|:--|:--|
| Modules | on | Must-have skills + `100x-resolver` to `~/.claude/skills/`, `/100x` route |
| Plugins | on | Adds 2 Claude Code plugins (GitHub, security guidance) to `~/.claude/settings.json` |
| Shell aliases | off | Prints how to load aliases for one terminal; never edits `~/.zshrc` / `~/.bashrc` |
| Templates | on | Copies 4 project templates to `~/100x-templates/` |
| Hooks | off | Enforcing hooks for Claude Code — see [Enforcing hooks](#enforcing-hooks) |

On macOS it also sets up the background token collector
([details](#monitoring-token-usage)). It runs the Hermes adapter if `~/.hermes` or the
`hermes` CLI exists, and lists [skill packs](#skill-packs) that match the current
directory.

### Step 2 — Project setup (once per project)

```bash
cd my-project && 100xprism init
```

`init` asks which tools you use **in this repo** — Claude Code, Cursor, Codex, Pi — and
writes:

| Tool | Files |
|:--|:--|
| Claude Code | `CLAUDE.md` scaffold and `.claude/100xprism.yml`, only if the repo has no `CLAUDE.md`, `AGENTS.md` or `.cursorrules` yet |
| Cursor | `.cursor/rules/*.mdc`, `.cursor/100xprism-catalog/` |
| Codex | `AGENTS.md` (unless you wrote your own), `.agents/`, `.codex/hooks.json` |
| Pi | `.pi/skills/`, `.pi/prompts/100x.md`, `.pi/100xprism-catalog/` |

`init` also records the project in `~/.100xprism/tracked-projects` so `update` keeps it
current, and removes files generated by the tools dropped in v3.0.0. **Commit the
generated files** so teammates get the same setup on clone.

### Step 3 — Start using

Restart Claude Code in the project and run `/gate`, `/test` or `/commit`.

> **Terminal vs AI tool.** `100xprism install | init | update | check | optimize | audit |
> tokens | value | uninstall` run in your **terminal**. Slash commands such as `/commit`
> run **inside the AI tool**. "command not found" usually means the wrong one.

## Using the modules

### Claude Code

There are 28 slash commands. In the default `must` mode, 12 of them are native: `/branch` `/commit` `/pr`
`/push` `/release` `/pair-loop` `/gate` `/test` `/lint` `/security` `/eval` `/docs`.

The other 16 command modules are in the catalog. Run them through the generic route,
using the module **slug**:

```
/100x spec
/100x fix-bugs "the login button returns 403"
/100x grill-me
/100x db
```

Or switch to `profile` mode (`100xprism optimize --skills=profile`) to make all 28 native,
including the short aliases `/fix`, `/grill`, `/query`, `/context` and `/update-claude`.

Useful arguments:

```
/release patch|minor|major   # bump, tag, publish, verify
/test --unit                 # unit tests only
/test --integration          # integration tests (starts Docker services)
/test --e2e                  # full docker compose stack
/test --e2e staging|prod     # E2E against a deployed environment
```

**Task-triggered playbooks.** The 40 marketing, SEO, CRO, design and engineering
playbooks have no command — describe the task:

- "Write homepage copy" → `copywriting`
- "Audit SEO on this page" → `seo-audit`
- "Optimize the signup flow" → `signup-flow-cro`
- "Audit this page for WCAG accessibility" → `a11y-auditor`
- "Pick the right chart for this dashboard" → `data-viz`

By default the always-loaded `100x-resolver` skill lists each playbook with its file
path, and the agent reads the one that matches. In `all` mode each is its own skill.

### Codex

Codex uses repo skills, not custom slash prompts:

```
$gate        # run the gate skill
$commit      # gate + stage + commit
/skills      # browse and pick
```

A Claude-style name such as "run /gate" in your prompt is treated as the matching skill
request — the generated `AGENTS.md` says so.

**Hooks are opt-in.** `.codex/hooks.json` contains hook groups only when you emit with
`PRISM_HOOKS=1`:

```bash
PRISM_HOOKS=1 python3 ~/100xprism/adapters/lib/modules.py emit-codex .
```

Then open `/hooks` in Codex to review and trust them. `gate-on-commit` blocks
`git commit`/`git push` until the gate passed for the current tree; `secret-scan` blocks
writes containing obvious credentials. Claude Code plugins do not install into Codex;
use Codex `/plugins`.

### Pi

Pi indexes every skill it finds, so 100xPrism installs the must-have set plus
`100x-resolver` rather than all 68.

```bash
# As a Pi package (Pi runs npm prepare → emit-pi-package)
pi install git:github.com/rajitsaha/100xprism

# Per project
cd my-project && 100xprism init          # choose Pi
# or: python3 ~/100xprism/adapters/lib/modules.py emit-pi .
```

Then `/skill:gate`, `/skill:commit`, or `/100x <workflow>` for catalog modules. The
gate/secret and retention extensions ship in `pi/extensions/` but are not auto-loaded;
enabling them is your choice. Set `"profiles": ["all"]` in `.100xprism.json` only if you
want every module indexed.

### Cursor

Rules load from their descriptions, so ask in plain words:

```
"Run the gate workflow before committing"
"Run the test workflow — I need 95% coverage"
"Follow the commit workflow"
```

`gate` (the only `tier: core` module) is written with `alwaysApply: true` and is always
in context. Every other rule loads when its description matches.

### Hermes/OpenClaw

`install` and `update` emit skills to `~/.hermes/skills/100xprism/` whenever Hermes is
detected; only that `100xprism/` folder is managed. If you install Hermes afterwards,
run `100xprism hermes`.

### Skill packs

Packs are optional vendor skill sets (today: **Databricks**). Inside Claude Code:

```
/pack                    # list packs, install state, matches for this project
/pack detect             # only matches for this project
/pack add databricks
/pack remove databricks  # removes only what 100xPrism installed
```

In `must` mode, use `/100x pack add databricks`. Pack state is tracked per install,
so removal never touches a plugin or command you enabled yourself.

### Daily flows

```
Typical:      /context → /spec or /fix → /test → /commit → /grill → /pr
Pre-release:  /context → /techdebt → /grill → /test → /gate → /pr → /launch → /release
Quick fix:    /fix "the login button returns 403" → /test → /commit → /pr
```

(In `must` mode, prefix catalog commands with `/100x`, e.g. `/100x spec`.)

## Project configuration

`init` scaffolds two files for Claude Code projects, split by how often they are read.

**`CLAUDE.md` — re-sent on every turn.** Keep only what a model cannot infer from the
code: project facts, non-obvious invariants, and a router to docs read on demand.

```markdown
## Project Overview
- Stack, hosting, database, auth — one bullet each.

## Key Conventions
- Non-obvious invariants ONLY — the things that cost a debugging session when
  guessed wrong (ID types, middleware ordering, enum/name mismatches).

## Reference docs (read on demand)

| When you are… | Read |
|---|---|
| writing or running tests | `docs/testing.md` |
| reasoning about services, data flow, layout | `docs/architecture.md` |

## Rules
# Project-specific rules. /update-claude appends here automatically.
```

A `CLAUDE.md` over ~5 KB is usually reference material that belongs in `docs/`;
`100xprism optimize` flags it.

**`.claude/100xprism.yml` — read on demand** by `/db`, `/query`, `/gate`,
`/cloud-security`, `/launch`, `/push` and `/security`. Uncomment what applies:

```yaml
# engine: postgres
# connection: default
# connections:
#   default:
#     host: localhost
#     port: 5432
#     name: mydb
#     user: myuser
#     auth: env:DB_PASSWORD

# gcp_project: my-gcp-project
# cloud_run_service: my-service
# region: us-central1

# production_url: https://example.com
# health_url: https://example.com/health

# security_exceptions:
#   - lodash CVE-2020-XXXX: dev dependency only, not in production bundle
```

Keep top-level keys **flush-left** — modules find them with an anchored `grep`, so an
indented key is invisible. Older projects that keep this config in `CLAUDE.md` still
work: modules read the yml first, then fall back to `CLAUDE.md`, `AGENTS.md` or
`.cursorrules`.

## Context modes

A module's description is re-sent on every turn; its body loads only when invoked. Each
module has a retention class (`retention_of()` in `adapters/lib/modules.py`):

| Class | Count | Installed in |
|:--|--:|:--|
| `must` | 12 | every mode |
| `profile` | 18 | `profile` and `all` (the 16 other slash-command modules, `subagents`, `terminal-setup`) |
| `resolver` | 38 | `all` only; otherwise a row in `100x-resolver` |

Two switches, both reversible:

| Scope | File → key | Values |
|:--|:--|:--|
| User (Claude Code, Hermes) | `~/.100xprism/config.json` → `skills` (or `PRISM_SKILLS`) | `must` (default) · `profile` · `all` |
| Project (Cursor, Codex, Pi) | `<project>/.100xprism.json` → `profiles` (or `PRISM_PROFILES`) | unset = must · detected list = widen · `["all"]` = every module |

`optimize` writes both and re-emits immediately:

```bash
100xprism optimize                    # must for user scope + the current project
100xprism optimize --skills=profile   # widen user scope; detect this project's profiles
100xprism optimize --skills=all       # every module
100xprism optimize --all-projects     # apply to every tracked project
100xprism optimize --dry-run          # show changes only
```

`optimize` acts on the **current directory** as a project unless you pass paths or
`--all-projects`, so run it from a project root. `slim` is an alias. Routed modules are
copied to `~/.100xprism/100xprism-catalog/` (or the project's catalog directory), never
deleted. Measure with `100xprism audit` or `100xprism tokens --print`.

## Keeping up to date

```bash
100xprism check                              # newer version available?
100xprism update                             # apply (asks to confirm)
~/100xprism/update.sh --yes                  # apply without the prompt
~/100xprism/update.sh --plugins-only         # refresh plugins only
100xprism update --no-slim                   # skip the one-time switch to must mode
```

`update`, in order:

1. Refuses to run if `~/100xprism` has local changes (commit or move them first).
2. Fetches `origin/main` and shows what changed, then asks to apply.
3. On macOS, stages the new token-collector runtime, then fast-forwards the clone.
4. Backs up `~/.claude/commands/` to `commands.bak.<timestamp>` (keeps the 3 newest).
5. Re-emits Claude Code skills in your mode and prunes generated skills/aliases that no
   longer exist. Your own skills and commands are never touched.
6. Reconciles plugins in `~/.claude/settings.json`: adds newly declared ones and removes
   ones 100xPrism added but has since dropped. Plugins you set yourself are left alone.
7. Syncs installed packs, refreshes **already-installed** hooks (never enables new ones),
   reconciles Hermes skills, and runs `claude plugin update` for each plugin.
8. Regenerates files in every tracked project and suggests matching packs.

Restart Claude Code afterwards. `update` exits non-zero if any tracked project failed to
reconcile, even though the global update succeeded.

**Removal guarantees.** A file is removed from your repo only if it (1) carries the
`Generated by 100xprism` marker in its first 10 lines, (2) resolves inside the project,
and (3) was first copied to `~/.100xprism/removed-artifacts/<timestamp>/<project-path>/`.

## Upgrading: what changes and what you do

### From 3.0.x or earlier 3.x

| What changes on your next `update` | Action needed |
|:--|:--|
| User scope switches to `must` **once**; other modules move to the catalog | None. Announced, recorded, and never re-applied. Undo: `100xprism optimize --skills=all`. Skip: `100xprism update --no-slim` |
| `commit`, `push`, `branch` no longer always-on in Cursor | None. Still invokable; enforcement is the `gate-on-commit` hook |
| New projects get a router-style `CLAUDE.md` + `.claude/100xprism.yml` | None. Existing `CLAUDE.md` files are never rewritten |

### From 2.4.x or earlier

| What changes | Action needed |
|:--|:--|
| Windsurf, Copilot, Gemini, Antigravity support removed (3.0.0) | Use Claude Code, Cursor, Codex, Pi or Hermes |
| `update` deletes generated `.windsurfrules`, `GEMINI.md`, `ANTIGRAVITY.md`, `.github/copilot-instructions.md` from tracked projects | Review `git status`, commit the deletions. Backups in `~/.100xprism/removed-artifacts/` |
| `systems-architect` → `enterprise-design`; `conversion-copy` → `copywriting` | Use the surviving module; old skill and alias are pruned |
| Dashboard and update check no longer start from your shell | Run `100xprism tokens` when you want it |
| Legacy `source …/aliases.sh` lines in rc files | `100xprism uninstall` removes them |

### Rolling back

```bash
100xprism optimize --skills=all                                        # full skill index
# per project: "profiles": ["all"] in <project>/.100xprism.json
cp -r ~/.100xprism/removed-artifacts/<timestamp>/<path>/. <project>/   # restore deleted files
cp -r ~/.claude/commands.bak.<timestamp>/. ~/.claude/commands/         # restore prior commands
```

## Enforcing hooks

Claude Code hooks that turn the gate from a reminder into a rule. Off by default; enable
them by re-running `100xprism install` and selecting **Hooks**. Full reference:
[hooks/README.md](../hooks/README.md).

| Hook | Default when enabled | Effect |
|:--|:--|:--|
| `pretooluse-gate.py` (gate-on-commit) | on | Blocks `git commit`/`git push` unless `/gate` passed for the current tree |
| `pretooluse-secret-scan.py` | on | Blocks writes containing obvious credentials |
| `posttooluse-lint.py` | off | Advisory lint after edits; never blocks |
| `permission-router.py` | off | Auto-approves known read-only commands |

## Multiple projects

`init` is interactive (it asks which tools to set up), so run it per repo:

```bash
for dir in ~/projects/*/; do
  [ -d "$dir/.git" ] && (cd "$dir" && 100xprism init)
done
```

**Team onboarding checklist:**

```
- [ ] Install: npm install -g 100xprism && 100xprism install
- [ ] Open the project; generated files are already committed
- [ ] Restart Claude Code and run /gate to verify
```

## GitHub Actions templates

```bash
mkdir -p .github/workflows
cp ~/100xprism/github-actions/ci.yml      .github/workflows/ci.yml
cp ~/100xprism/github-actions/release.yml .github/workflows/release.yml
```

**`ci.yml`** — every push and every PR to `main`/`master`:

| Job | What it does |
|:--|:--|
| `lint` | ESLint, `tsc --noEmit`, ruff — each only if the project uses it |
| `unit-tests` | Unit + integration tests against Postgres 16 + Redis 7 service containers; 95% coverage enforced |
| `e2e-tests` | Full `docker compose` stack, smoke tests, then Playwright. Skipped without `playwright.e2e.config.*` or `e2e/` |

**`release.yml`** — on `v*.*.*` tags: tests → build → GitHub Release → publish to
PyPI/npm/Docker Hub → verify from the registry → optional Homebrew tap update.

Secrets: `DOCKERHUB_USERNAME`, `DOCKERHUB_TOKEN` (Docker), `NPM_TOKEN` (npm),
`HOMEBREW_TAP_TOKEN` (optional). PyPI uses OIDC trusted publishing — no secret. Jobs that
don't apply are skipped.

The three CI traps these templates guard against (`# TRAP:` comments) are explained in
[ci-traps.md](ci-traps.md).

## Monitoring token usage

```bash
100xprism tokens                          # start and open the dashboard
100xprism tokens --no-open                # start without opening a browser
100xprism tokens --print                  # text summary, no server
100xprism tokens --json                   # versioned machine-readable report
100xprism tokens --json --tool codex      # one source only
100xprism tokens --oneline                # one-line summary for a shell prompt
100xprism value                           # git delivery report for the current directory
```

The dashboard serves at `http://127.0.0.1:8787`. Nothing starts it automatically — not
your shell, not `init`, not `update`. `100xprism install --dashboard` starts it once after
installing.

### Sources

| Source | Measured | Cost |
|:--|:--|:--|
| Claude Code (incl. subagents) | Exact local token counters | Priced per model |
| Codex | Exact local token counters | Priced per model |
| Pi | Records that carry token counters | Priced when counted |
| Cursor | Activity from `~/.cursor/projects/*/agent-transcripts/**.jsonl` | `—` (no counters) |
| Antigravity | Conversations and task artifacts | `—` (no counters) |

Prices come from `scripts/pricing.py`, a dated catalog with source links. Unknown model
IDs fall back to a default rate; the dashboard reports the share of spend priced that
way. Cursor chats, `state.vscdb` and legacy `.txt` transcripts are not read.

### macOS: background collection

`install` adds a LaunchAgent that runs once a minute and at login, then exits. It needs
Node 18+ (installs via `curl` without Node skip it until you install Node and rerun
`install.sh` or `update.sh`).

- Data lives in a private SQLite store under `~/.100xprism/token-economics/current/`.
  The first run scans all transcripts; later runs parse only newly appended records.
  Totals survive deleted transcripts.
- The page shows the latest snapshot immediately and polls every 30 seconds.
- The server needs a per-launch token (`100xprism tokens` opens the right URL), checks
  CSRF tokens on changes, and exits after 10 minutes without traffic.
- `100xprism tokens --verify-history` runs the daily integrity pass by hand (at most
  32 MiB of history per run).
- `100xprism uninstall` stops collection and keeps history; `uninstall --purge` deletes
  it. Removing the npm package alone leaves the collector running.

**Content search (opt-in).** `100xprism tokens --enable-content-search` indexes your
prompts and the assistant's prose with SQLite FTS5 — no embeddings, no network. Tool
output and file contents are excluded; records over 1 MiB are skipped.
`--disable-content-search` removes indexed text from the databases (older filesystem
backups may still hold it).

**Linux and Windows** compute reports on demand when you run `100xprism tokens` and
print "Background token economics is coming soon for this platform." The background and
content-search flags do nothing there.

### What the dashboard shows

The Economics view keeps three layers apart:

1. **Token economics** — tokens and estimated list-price spend (input, output, cache
   read, cache write), a startup-bloat meter, by project, model, day, session and skill.
2. **Observable delivery** — commits, merged PRs, releases, files and churn from git,
   with the share of spend that could be attributed. Non-git directories use a labeled
   file-modification-time estimate.
3. **Business value** — **Not measured** until you connect an outcome source (adoption,
   revenue, incidents avoided, verified time saved).

`$/PR` and `$/commit` are delivery unit costs from attributed spend only — not ROI and
not a performance score. Also shown: main-vs-subagent split, pair-loop run costs,
lifetime cache savings, and ranked offline recommendations.

### Budgets

Add to `~/.100xprism/config.json`; every key defaults to `null` (off):

```json
{
  "budget": { "daily_usd": 25, "weekly_usd": 150, "per_run_usd": null }
}
```

You get a budget bar, a `⚠`/`‼` marker in `--oneline`, and an OS notification the first
time a period crosses 80% and 100%.

### GitHub PR insights (opt-in)

With `gh auth login` done, add:

```json
{
  "github": {
    "enabled": true,
    "users": ["octocat"],
    "repos": ["acme/example-service"],
    "max_repos": 12,
    "max_prs_per_repo": 30,
    "max_pr_file_fetches_per_repo": 3,
    "max_user_repos_per_user": 20
  }
}
```

The dashboard then fetches PRs for your local GitHub remotes plus these users and repos:
status, author, comments, churn, and (sampled) file detail, cached for 30 minutes. On
macOS the fetch runs only when you click **Fetch GitHub insights**; scheduled collection
never calls GitHub.

To shrink spend rather than measure it, see [token-optimization.md](token-optimization.md).

## Troubleshooting

| Problem | Fix |
|:--|:--|
| `command not found: 100xprism` | `npm install -g 100xprism`; with mise, also `mise reshim node` |
| Slash command not recognized | Restart Claude Code. In `must` mode, catalog commands run as `/100x <slug>` |
| A module is "missing" after `update` | It moved to the catalog: `/100x <slug>`, or `100xprism optimize --skills=profile` |
| `update` says "Refusing update: stable clone has … changes" | Something edited `~/100xprism`. `cd ~/100xprism && git status`, then commit, stash or discard |
| `source: no such file: …/100xprism/shell/aliases.sh` | Legacy rc-file line: `100xprism uninstall`, or delete the line |
| `SessionStart:startup hook error` | Legacy hook: run `100xprism audit --fix` or `100xprism install` |
| `/gate` fails at the Docker step | The Docker gate runs when a `Dockerfile` exists; start Docker Desktop |
| Codex skill not appearing | Restart Codex, run `/skills`, check `.agents/skills/<slug>/SKILL.md` exists |
| Codex hook not running | Emit with `PRISM_HOOKS=1`, then trust it in `/hooks` |
| Claude Code plugin not active | Check `enabledPlugins` in `~/.claude/settings.json`, restart Claude Code |
| Dashboard URL shows unauthorized (macOS) | Open it with `100xprism tokens`, which adds the access token |

## FAQ

**Does this work without an AI coding tool?** No. Modules are instructions for an AI
agent; without one they are just markdown.

**Can I use only some modules?** Yes. Modules are independent, and the default `must`
mode installs only 12.

**Will the gate slow me down?** It adds checks before each commit. Catching failures
locally is faster than debugging them in CI or production.

**How do I add a database engine?** Add `modules/db/db-engines/<engine>.md` following the
existing engines and open a PR. Don't edit `~/100xprism` directly: `update` refuses to
run on a clone with local changes.

**How do I contribute a module or adapter?** Read [AGENTS.md](../AGENTS.md): it covers
frontmatter, retention, the adapters, and the checks to run (`npm run check`).
